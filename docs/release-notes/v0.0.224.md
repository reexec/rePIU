## rePIU v0.0.224

이전 릴리스 **v0.0.223** 이후의 변경입니다(issue #72 후속). **브라우저 페이지를 쓰기 쉽게 했습니다.** 롬을 폴더 하나로도 고를 수
있고, 시작한 뒤 무엇을 하고 있는지 페이지에서 바로 보입니다. 배포 빌드(Windows·Linux)는 첫 실행에 진행 줄이 더 나오는 것 말고는
바뀌지 않습니다.

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#72](https://github.com/reexec/rePIU/issues/72) 후속 | 롬을 폴더 하나 또는 ZIP·CHD 각각으로 고르기, CHD 풀기 진행을 페이지에 보이기 | `67b6e43` |

### 바뀐 것

**롬 고르기.** 지금까지는 파일 칸 하나로 ZIP과 CHD를 함께 골라야 했는데, 둘은 보통 다른 폴더(`roms/pumpitea.zip`,
`roms/pumpitea/010209_1821.chd`)에 있어 한 번에 고를 수 없었습니다.

* **폴더 하나:** `roms`처럼 게임 ZIP과 그 CHD가 든 폴더를 고르면 게임을 찾아 줍니다. 여러 게임이 있으면 목록에서 고릅니다.
  ZIP과 CHD가 한 폴더에 나란히 있어도 됩니다. 폴더의 다른 ZIP도 함께 넘겨, 부모 롬셋(`pumpite.zip` 등)이 필요한 경우에도 됩니다.
* **각각:** ZIP 칸과 CHD 칸이 따로 있습니다.
* 파일은 사이트로 올라가지 않고 브라우저 안에서만 읽습니다.

**진행이 보이는 페이지.** 시작한 뒤 1분 넘게 아무것도 나오지 않던 것은, CHD에서 게임 파일(pumpitea는 736개, 409 MB)을 푸는
동안 엔진이 한 줄도 찍지 않았기 때문입니다.

* 엔진이 풀기 시작과 약 16 MB마다 진행률을 찍습니다. 예: `pumpitea unpacked 47% (194/736 files, 192/409 MB)`. Windows·Linux의
  첫 실행에서도 같은 줄이 나옵니다.
* 페이지는 엔진 출력을 캔버스 옆(좁은 화면에서는 아래)에 두고, 경과 시간·줄 수·마지막 줄을 계속 보여 줍니다. 로그 전체를
  복사하는 버튼이 있습니다.

### 확인한 것

### 알려진 것

* 웹에서는 아직 키보드·게임패드 입력과 소리가 없습니다(다음 단위). 그래서 F5(COIN1)를 누르면 브라우저가 새로고침됩니다.

## rePIU v0.0.224

Changes since **v0.0.223** (a follow-up to issue #72). **The browser page is easier to use:** the ROMs can be picked as
one folder, and what the engine is doing after Start shows on the page. Release builds (Windows, Linux) are unchanged
apart from extra progress lines on a first run.

### Resolved issues

| issue | Summary | Commit |
|---|---|---|
| [#72](https://github.com/reexec/rePIU/issues/72) follow-up | pick the ROMs as one folder or as the ZIP and the CHD separately; show the CHD unpack's progress on the page | `67b6e43` |

### Changed

**Picking the ROMs.** Until now one file field had to pick the ZIP and the CHD together, but the two usually sit in
different folders (`roms/pumpitea.zip`, `roms/pumpitea/010209_1821.chd`), so they could not be picked at once.

* **One folder:** pick a folder holding the game's ZIP and its CHD, such as `roms`, and the game is found; with several
  games, one is chosen from a list. A ZIP and a CHD side by side in one folder work too. The folder's other ZIPs go along,
  so a game that needs its parent ROM set (`pumpite.zip` and the like) works as well.
* **Separately:** a ZIP field and a CHD field.
* Nothing is uploaded; the browser only reads the files.

**A page that shows its progress.** Nothing appeared for over a minute after Start because the engine printed no line
while it unpacked the game's files from the CHD (736 files, 409 MB for pumpitea).

* The engine reports the unpack's start and its progress about every 16 MB, for example
  `pumpitea unpacked 47% (194/736 files, 192/409 MB)`. Windows and Linux print the same lines on a first run.
* The page shows the engine's output beside the canvas (below it on a narrow screen), with the elapsed time, the line
  count and the latest line kept current, and a button that copies the whole log.

### Verified

Browser: the user ran the game with the new page; in headless Edge, picking by folder and separately, starting, and
progress lines within 3 s of starting. The picking rules: a Node test 11/11, and all 16 games found in this PC's real
`roms/`. Win32 `direct` Release: 26 progress lines from an empty cache, the unpack done in 21 s. Web (`repiu`,
`repiu_browser`): builds. CI: the Win32 Debug build and probes.

### Known

* The web build has no keyboard or gamepad input and no sound yet (the next unit), so F5 (COIN1) reloads the page.
