## rePIU v0.0.230

이전 릴리스 **v0.0.229** 이후의 변경입니다. **화면 shader가 여러 pass를 잇는 `.glslp` preset을 읽고, 내장 업스케일러
`fsr`·`scalefx`·`anime4k`가 생겼습니다.**

### 반영된 issue

| issue | 내용 | PR |
|---|---|---|
| [#90](https://github.com/reexec/rePIU/issues/90) | 화면 shader: `fsr`·`scalefx`·`anime4k` 업스케일러와 다단계 `.glslp` shader 체인 (re2DJ #26·#27처럼) | [#91](https://github.com/reexec/rePIU/pull/91) |

### 바뀐 것

* **내장 업스케일러(#90):** 런처 Options의 "Screen shader", `--post-shader`, `REPIU_POST_SHADER`로 고릅니다.
  | 이름 | 내용 | pass | 매개변수 |
  |---|---|---|---|
  | `fsr` | AMD FidelityFX Super Resolution 1(EASU 확대 + RCAS 선명화) | 2 | 1 |
  | `scalefx` | ScaleFX(Sp00kyFox, libretro glsl-shaders) | 5 | 3 |
  | `anime4k` | Anime4K v3.2 Upscale CNN x2 S(bloc97) | 5 | 0 |

  세 파일 묶음은 re2DJ #26·#27의 것을 그대로 옮겼고, 출처와 MIT 고지를 `THIRD_PARTY_NOTICES.md`에 더했습니다.
* **다단계 preset(#90):** `shaders/`의 `.glslp` 파일이 여러 pass를 잇습니다. libretro preset 형식의 부분집합으로
  `scale_type`·`scale`(축별 포함), `filter_linear`, `float_framebuffer`, `OrigTexture`, `PassPrevN`을 읽습니다.
  libretro의 `#version 130` 스타일 pass도 그대로 읽힙니다. 형식은 `docs/guides/post-process-shaders.md`.
* **실패할 때:** pass 대상(`RGBA8`·`RGBA16F`)을 만들 수 없으면 shader를 내리고 평범하게 그립니다. 로그 줄에
  pass 수가 붙습니다(예: `[repiu-post] shader: anime4k (5 passes, 0 parameters)`).

### 확인한 것

| 구성 | 확인 |
|---|---|
| Win32 Debug·Release | 빌드, `repiu_aot_probe --post-shader`(preset 파서, 내장, `.glslp` 목록), `repiu_glide_render_probe --opengl-post-shader`(실제 GL에서 세 체인) |
| Linux x64 Debug | 빌드 |
| 실제 실행 | 사용자가 게임에서 세 업스케일러 동작 확인 |

### 알려진 것

* 웹 빌드는 돌려 보지 못했습니다. 코드는 GL 3.3 core / ES 3.0 공용 부분집합만 쓰지만, 브라우저에서 세 preset의
  ES 컴파일과 `RGBA16F` 대상은 다음 웹 빌드에서 확인할 항목입니다.
* `srgb_framebuffer`, `wrap_mode`, `mipmap_input`, `alias`, LUT 텍스처, 이전 프레임(`PrevTexture`)은 지원하지 않습니다.

## rePIU v0.0.230

Changes since **v0.0.229**. **Screen shaders read multi-pass `.glslp` presets, and the built-in upscalers `fsr`,
`scalefx` and `anime4k` are new.**

### Issues addressed

| issue | Summary | PR |
|---|---|---|
| [#90](https://github.com/reexec/rePIU/issues/90) | Screen shader: the fsr, scalefx and anime4k upscalers and multi-pass `.glslp` shader chains, as in re2DJ #26/#27 | [#91](https://github.com/reexec/rePIU/pull/91) |

### Changed

* **Built-in upscalers (#90):** picked under "Screen shader" in the launcher's Options, with `--post-shader`, or with
  `REPIU_POST_SHADER`.
  | Name | What | Passes | Parameters |
  |---|---|---|---|
  | `fsr` | AMD FidelityFX Super Resolution 1 (EASU upscale + RCAS sharpening) | 2 | 1 |
  | `scalefx` | ScaleFX (Sp00kyFox, libretro glsl-shaders) | 5 | 3 |
  | `anime4k` | Anime4K v3.2 Upscale CNN x2 S (bloc97) | 5 | 0 |

  The three file sets are re2DJ #26 and #27's, carried over; their origins and MIT notices are in
  `THIRD_PARTY_NOTICES.md`.
* **Multi-pass presets (#90):** a `.glslp` file in `shaders/` chains passes. It is a subset of the libretro preset
  format: `scale_type` and `scale` (per axis too), `filter_linear`, `float_framebuffer`, `OrigTexture` and `PassPrevN`.
  libretro's `#version 130` style passes are read as they are. The format is in `docs/guides/post-process-shaders.md`.
* **On failure:** when a pass target (`RGBA8` or `RGBA16F`) cannot be made, the shader is dropped and the picture is
  drawn plainly. The log line carries the pass count (`[repiu-post] shader: anime4k (5 passes, 0 parameters)`, for
  one).

### Checked

| Configuration | Check |
|---|---|
| Win32 Debug and Release | build, `repiu_aot_probe --post-shader` (the preset parser, the built-ins, the `.glslp` listing), `repiu_glide_render_probe --opengl-post-shader` (the three chains in a real GL) |
| Linux x64 Debug | build |
| A real run | the user checked the three upscalers in the game |

### Known

* The web build was not run. The code uses only the shared GL 3.3 core / ES 3.0 subset, but the ES compile of the three
  presets and the `RGBA16F` targets in a browser are items for the next web build.
* `srgb_framebuffer`, `wrap_mode`, `mipmap_input`, `alias`, LUT textures and the previous frame (`PrevTexture`) are not
  supported.
