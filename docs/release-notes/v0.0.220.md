## rePIU v0.0.220

이전 릴리스 **v0.0.219** 이후의 변경입니다(issue #64, #61 후속). **브라우저 호스트의 첫 단계입니다.** 브라우저의 단일
Worker에는 스레드가 없으므로, 개발용 `emulated` 모델이 게임 코드·화면·타이머·소리·입력을 한 스레드에서 번갈아
처리하게 했습니다. 배포 빌드(Windows·Linux)의 동작은 바뀌지 않습니다.

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#64](https://github.com/reexec/rePIU/issues/64) | 웹 이식 2B: 브라우저 호스트 설계, 단계 1(`emulated`의 단일 스레드 호스트 루프) | `3288e17` |
| [#61](https://github.com/reexec/rePIU/issues/61) 후속 | 실행 모델 셋을 규칙·구조 문서에 반영, Linux i386 빌드 수정 | `3288e17` |

### 바뀐 것

**단일 스레드 호스트 루프.** 지금까지 rePIU는 게임 코드를 도는 스레드와, 화면·타이머·창을 맡는 메인 스레드, 오디오
스레드들로 나뉘어 있었습니다. `emulated`에서는 이제 메인 스레드 하나가 rex86으로 게임 코드를 조금 돌리고, 다음
타이머 tick이 되거나 2 ms가 지나면 호스트 일(창 이벤트, 화면, 타이머, 오디오 채우기)을 하는 것을 되풀이합니다.

* **설계:** 브라우저 호스트를 네 단계로 나눴습니다. 1) 단일 스레드 루프(이번), 2) Emscripten 빌드와 Node 헤드리스
  실행, 3) Glide 렌더러를 WebGL2로, 4) 브라우저 페이지(Worker, OPFS, AudioWorklet, 입력).
* **결과(Windows, pumpitea):** 사용자가 로고·오프닝 영상·음악 출력을 확인했습니다. 단계 1 전후의 HLE 경계 trace가 첫
  벽시계 의존까지 같습니다.
* **처리량:** 실행 명령 수는 29% 줄었지만 화면 교체 수는 같고 게임의 진행은 같거나 앞섰습니다. 줄어든 것은 게임이
  기다리며 도는 루프입니다(추정). 따라서 "초당 명령 수"는 `emulated`의 진행 지표로 맞지 않습니다.
* **공용 코드:** 호스트 일 한 번(`HostTurn`)을 폴링 루프에서 뽑았고, 오디오 출력 셋과 입력 스크립트를 한 단계씩
  돌릴 수 있게 했습니다. `direct`·`cache`는 이것을 전과 같이 스레드에서 되풀이합니다.

**#61 후속.** v0.0.219부터 Linux i386 빌드가 컴파일되지 않던 것(`_mm_getcsr`)을 고쳤습니다. AGENTS.md,
CODING_STYLE.md, ARCHITECTURE.md가 실행 모델을 셋으로 적습니다.

### 알려진 것

* `emulated`는 여전히 느려서, 측정한 PC에서는 타이틀까지 가지 못했습니다.
* `emulated`로 음악 뒤까지 돌린 사용자 실행 1회가 종료 중 힙 손상으로 크래시했습니다. 재현은 되지 않았고 다음 작업에서
  봅니다([#65](https://github.com/reexec/rePIU/issues/65)).

## rePIU v0.0.220

Changes since **v0.0.219** (issue #64, and #61 follow-ups). **The browser host's first phase.** The browser's single
Worker has no threads, so the development `emulated` model now runs the game's code, the screen, the timer, the sound and
the input on one thread, taking turns. Release builds (Windows, Linux) behave as before.

### Resolved issues

| issue | Summary | Commit |
|---|---|---|
| [#64](https://github.com/reexec/rePIU/issues/64) | Web port 2B: the browser host's design and phase 1 (the single-threaded host loop of `emulated`) | `3288e17` |
| [#61](https://github.com/reexec/rePIU/issues/61) follow-up | The three execution models in the rules and architecture documents; the Linux i386 build fixed | `3288e17` |

### Changed

**The single-threaded host loop.** rePIU used to split into a thread running the game's code, a main thread for the
screen, the timer and the window, and audio threads. On `emulated` one main thread now runs the game's code on rex86 for
a while and, when the next timer tick is due or 2 ms have passed, does the host's work (window events, the screen, the
timer, filling the audio), over and over.

* **Design:** the browser host comes in four phases: 1) the single-threaded loop (this release), 2) the Emscripten build
  and a headless run under Node, 3) the Glide renderer on WebGL2, 4) the browser page (Worker, OPFS, AudioWorklet,
  input).
* **Result (Windows, pumpitea):** the user confirmed the logo, the opening video and the music. The HLE boundary trace
  before and after phase 1 matches up to the first wall-clock dependence.
* **Throughput:** the instructions run fell by 29%, but the buffer swaps are equal and the game's progress is equal or
  ahead; what went is the loops the game runs while waiting (inferred). Instructions per second is therefore not a
  measure of `emulated`'s progress.
* **Shared code:** one turn of the host's work (`HostTurn`) was taken out of the poll loop, and the three audio outputs
  and the input script can be run one step at a time. `direct` and `cache` repeat them on threads as before.

**#61 follow-ups.** The Linux i386 build, which had not compiled since v0.0.219 (`_mm_getcsr`), is fixed. AGENTS.md,
CODING_STYLE.md and ARCHITECTURE.md name three execution models.

### Verified

Win32 `direct` Release: core probe 44/44, pumpitea 3,600 frames in 70 s, clean exit. Win32 `emulated` Release: core
probe 44/44, the boundary trace comparison, the input script, window close and timeout, and the user's check (logo,
opening, music). Linux i386 and x64 (WSL): build and core probe. CI: the Win32 Debug build and probes.

### Known

* `emulated` is still slow; on the measuring PC it did not reach the title.
* One user run of `emulated` past the music crashed with heap corruption during teardown. It has not reproduced and is
  the next task's ([#65](https://github.com/reexec/rePIU/issues/65)).
