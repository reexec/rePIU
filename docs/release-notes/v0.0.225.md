## rePIU v0.0.225

이전 릴리스 **v0.0.224** 이후의 변경입니다(issue #76). **웹 페이지에서 키보드와 게임패드로 게임을 조작합니다.** 키 배치는
Windows·Linux와 같습니다. 배포 빌드(Windows·Linux)의 동작은 바뀌지 않습니다.

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#76](https://github.com/reexec/rePIU/issues/76) | 브라우저 페이지의 키보드·게임패드 입력(단계 4 단위 2의 입력 부분). 게임 안 확인은 남아 issue는 열어 둠 | `3f4c8e8` |

### 바뀐 것

**키보드.** 지금까지 웹에는 입력이 없어 F5(COIN1)를 누르면 브라우저가 새로고침되었습니다.

* 게임이 도는 동안 페이지가 키를 엔진으로 보내고, 엔진은 네이티브 창의 키처럼 받습니다. 그래서 키 배치가 그대로입니다:
  동전 `F5`, 테스트 `F1`, 서비스 `F2`, 클리어 `F3`, P1 `Q` `E` `S` `Z` `C`, P2 키패드 `7` `9` `5` `1` `3`, OSD `Tab`.
* 키는 글자가 아니라 키의 자리(`KeyboardEvent.code`)로 보내므로, 키보드 배열과 관계없이 같은 키가 같은 입력입니다.
* 게임 키의 브라우저 기본 동작을 막습니다. F5는 새로고침하지 않고, Tab은 초점을 옮기지 않습니다. Ctrl·Meta 조합, F11(전체 화면),
  F12(개발자 도구)는 브라우저 몫으로 남깁니다.
* 페이지가 초점을 잃거나 숨겨지면 눌린 키를 모두 뗍니다(네이티브 창과 같음).
* 페이지에 키 안내가 있습니다.

**게임패드.** 브라우저가 표준 매핑으로 알아보는 패드(대부분의 XInput 패드)를 SDL 게임패드로 넘겨, 네이티브의 패드 바인딩과
조합이 그대로 적용됩니다: 동전 Back, OSD LT+RT+Y, 종료 LT+RT+L3+R3. 표준 매핑이 아닌 패드는 쓰지 않고 콘솔에 한 번 알립니다.

### 알려진 것

* **게임 안에서 동전·OSD가 반응하는지, 게임패드가 동작하는지는 아직 브라우저에서 확인하지 못했습니다.** 이 PC에서 headless 브라우저의
  파일 읽기가 느려져 CHD 풀기에서 멈췄습니다(이 변경 전 빌드도 같음). 사용자 확인이 남아 #76을 열어 둡니다.
* 웹에는 아직 소리가 없습니다(다음 단위).
* Win32에서 pumpitea의 첫 텍스처 업로드에 GL 오류가 기록될 때가 있습니다. v0.0.224에도 있으며 [#78](https://github.com/reexec/rePIU/issues/78)에서 다룹니다.

## rePIU v0.0.225

Changes since **v0.0.224** (issue #76). **The game can be played with the keyboard and gamepads on the web page,** with the
same key layout as on Windows and Linux. Release builds (Windows, Linux) behave as before.

### Resolved issues

| issue | Summary | Commit |
|---|---|---|
| [#76](https://github.com/reexec/rePIU/issues/76) | keyboard and gamepad input on the browser page (the input part of phase 4 unit 2); the issue stays open for the in-game check | `3f4c8e8` |

### Changed

**Keyboard.** Until now the web build had no input, so F5 (COIN1) reloaded the page.

* While the game runs, the page sends keys to the engine, which takes them as a native window's keys, so the layout is
  the same: coin `F5`, test `F1`, service `F2`, clear `F3`, P1 `Q` `E` `S` `Z` `C`, P2 keypad `7` `9` `5` `1` `3`, the OSD `Tab`.
* Keys go by the key's position (`KeyboardEvent.code`), not the character, so the same key is the same input whatever the
  keyboard layout.
* The browser's default action for game keys is stopped: F5 does not reload and Tab does not move the focus. Ctrl and
  Meta combinations, F11 (fullscreen) and F12 (developer tools) stay the browser's.
* When the page loses focus or is hidden, every held key is let go of (as a native window does).
* The page lists the keys.

**Gamepads.** A pad the browser recognises with the standard mapping (most XInput pads) is handed to SDL as a gamepad, so the
native pad bindings and chords apply as they are: coin on Back, the OSD on LT+RT+Y, exit on LT+RT+L3+R3. A pad without the
standard mapping is not used, and the console says so once.

### Verified

| Configuration | Check |
|---|---|
| Browser | in headless Edge, F5 does not reload the page |
| Key name table | core probe `browser_key_code` (ranges, named keys, every key of the default layout, unknown names): Win32, Linux x64 and i386, web |
| Win32 `direct` Release | core probe 45/45, pumpitea stops normally after 40 s |
| Linux x64 and i386 Release | core probe 47/47 and 45/45 |
| Web (`repiu`, `repiu_browser`, `repiu_core_probe`) | build; Node core probe 37/37 |
| CI | the Win32 Debug build and probes |

### Known

* **Whether the coin and the OSD react in the game, and whether gamepads work, has not been checked in a browser yet.** On
  this PC headless browsers' file reads had slowed down and the CHD unpack stalled (the build before this change as well).
  #76 stays open for the user's check.
* The web build has no sound yet (the next unit).
* On Win32 a GL error is sometimes recorded at pumpitea's first texture upload. v0.0.224 has it too; it is
  [#78](https://github.com/reexec/rePIU/issues/78).
