## rePIU v0.0.221

이전 릴리스 **v0.0.220** 이후의 변경입니다(issue #67). **브라우저 호스트의 두 번째 단계입니다.** 개발용 `emulated`
엔진과 CPU 에뮬레이터 rex86을 WebAssembly로 빌드해, Node에서 pumpitea를 화면 없이 실행합니다. 배포 빌드(Windows·Linux)의
동작은 바뀌지 않습니다.

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#67](https://github.com/reexec/rePIU/issues/67) | 웹 이식 2B 단계 2: `emulated` 엔진과 rex86의 Emscripten 빌드, Node 헤드리스 실행 | `27e894d` |

### 바뀐 것

**웹 빌드가 게임을 실행합니다.** 지금까지 웹 빌드는 게임을 실행하지 않는 공용 코어만 빌드했습니다. 이제 엔진 전체를
`emulated` 모델로 빌드하며, 게임 코드는 rex86이 wasm 안에서 실행합니다.

* **결과(pumpitea, Node):** 30초 동안 약 6.1 MIPS로 돌았습니다. 같은 PC의 네이티브 `emulated`와 비슷한 속도입니다.
  HLE 경계 trace가 네이티브와 첫 벽시계 의존까지 같습니다(이미지가 놓인 주소 차이 제외). 화면은 Glide dummy, 소리는
  없습니다(단계 3·4에서 화면과 소리).
* **메모리:** 게임의 주소를 wasm 메모리의 같은 주소에 두고, Emscripten의 데이터·스택·힙은 `0x10000000` 위로 옮겼습니다.
* **웹 플랫폼 계층:** 가상 메모리(stub → 구현), 합성한 호스트 진입 상태(Windows 스레드가 보는 셀렉터 값), 스레드 없는
  스레드 계층, 진단용 "없음" 답들. Glide 백엔드가 아직 쓰는 고정 기능 GL 11개는 불리면 멈추는 임시 stub입니다.
* **실행:** `./scripts/build_web_wasm.sh --build-dir ~/repiu-web`로 빌드하고, 저장소 루트에서
  `node ~/repiu-web/repiu.js pumpitea`로 실행합니다.
* 쓰지 않게 된 실행 모델 `none`을 지웠습니다.

* 브라우저에서는 아직 돌지 않습니다. 다음은 Glide 렌더러를 WebGL2로 옮기는 단계 3입니다.
* 웹에서는 런처를 쓸 수 없습니다(업데이트 확인이 스레드를 씀).
* `emulated` 종료 중 힙 손상 크래시(사용자 실행 1회)는 재현되지 않아 확인 중입니다([#65](https://github.com/reexec/rePIU/issues/65)).

## rePIU v0.0.221

Changes since **v0.0.220** (issue #67). **The browser host's second phase.** The development `emulated` engine and the
rex86 CPU emulator are built as WebAssembly, and run pumpitea under Node with no screen. Release builds (Windows, Linux)
behave as before.

### Resolved issues

| issue | Summary | Commit |
|---|---|---|
| [#67](https://github.com/reexec/rePIU/issues/67) | Web port 2B phase 2: the Emscripten build of the `emulated` engine and rex86, run headless under Node | `27e894d` |

### Changed

**The web build runs the game.** Until now the web build built only the shared core, which runs no game. It now builds
the whole engine on the `emulated` model, with the game's code run by rex86 inside wasm.

* **Result (pumpitea, Node):** about 6.1 MIPS over 30 s, close to native `emulated` on the same PC. The HLE boundary trace
  matches native up to the first wall-clock dependence (the image's placement aside). The screen is the Glide dummy and
  there is no sound (picture and sound come in phases 3 and 4).
* **Memory:** the game's addresses sit at the same addresses in wasm memory, with Emscripten's data, stack and heap moved
  above `0x10000000`.
* **Web platform layer:** virtual memory (stub → implementation), a synthesised host entry state (the selector values a
  Windows thread sees), a thread layer without threads, and "none" answers for the diagnostics. The 11 fixed-function GL
  calls the Glide backend still makes are temporary stubs that stop the run if reached.
* **Running:** build with `./scripts/build_web_wasm.sh --build-dir ~/repiu-web` and run
  `node ~/repiu-web/repiu.js pumpitea` from the repository root.
* The unused `none` execution model is deleted.

### Verified

Web (Node): `repiu` links, core probe 36/36, pumpitea for 30 s, the boundary trace comparison. Win32 `direct` and
`emulated` Release: core probe 44/44, pumpitea runs. Linux i386 and x64 (WSL): build and core probe. CI: the Win32 Debug
build and probes.

### Known

* It does not run in a browser yet; next is phase 3, moving the Glide renderer to WebGL2.
* The launcher cannot be used on the web (its update check uses a thread).
* The heap-corruption crash in `emulated` teardown (one user run) has not reproduced and is being looked into
  ([#65](https://github.com/reexec/rePIU/issues/65)).
