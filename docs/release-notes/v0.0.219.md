## rePIU v0.0.219

이전 릴리스 **v0.0.218** 이후의 변경입니다(issue #61). **웹(WebAssembly) 이식을 재개했습니다.** 첫 단계로, 게임
코드를 PC의 CPU가 아니라 CPU 에뮬레이터 [rex86](https://github.com/reexec/rex86)이 실행하는 새 실행 모델
`emulated`를 더했습니다. Windows에서 pumpitea가 이 모델로 타이틀과 데모 플레이까지 나옵니다. 배포 빌드는 바뀌지
않습니다. `emulated`는 개발용으로 따로 빌드합니다.

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#61](https://github.com/reexec/rePIU/issues/61) | 웹 이식 재개: rex86 위의 emulated 실행 모델, 네이티브 먼저(단계 2A) | `1c9dc58` |

### 바뀐 것

**`emulated` 실행 모델.** 지금까지 rePIU의 실행 모델 둘(`direct`, `cache`)은 모두 PC의 x86 CPU가 게임 코드를 직접
실행했습니다. 그래서 브라우저나 ARM 기기에서는 돌 수 없었습니다. `emulated`에서는 rex86(v0.0.34)이 게임의 x86
명령을 하나씩 해석해 실행하고, rePIU 프로세스는 게임 코드를 하나도 직접 실행하지 않습니다.

* **DOS·DPMI·Glide 등 기존 HLE는 그대로입니다.** rex86이 Windows 사용자 모드 프로세스에서 폴트가 나는 바로 그
  자리에서 멈추게 했습니다(rex86 [#69](https://github.com/reexec/rex86/issues/69)). HLE가 맡을 명령은 평소
  쓰는 `dynamic` 백엔드와 같은 규칙으로 고릅니다(rex86 [#70](https://github.com/reexec/rex86/issues/70)).
* **결과(Windows x86 Release, pumpitea):** 300초에 타이틀, 355초에 데모 플레이가 나왔고, 직접 플레이해 동작을
  확인했습니다. 다만 아직 느립니다. 초당 약 930만 명령(약 7.4fps)이고, 평소 빌드는 30초에 타이틀이 나옵니다.
* **측정:** 게임 한 프레임에 약 125만 명령이 들어갑니다. 실시간(60fps)에는 약 75 MIPS가 필요하다는 추정치이고,
  웹에서 무엇을 더 빠르게 해야 하는지 정하는 근거가 됩니다.
* **빌드:** `cmake -A Win32 -DREPIU_EXECUTION_MODEL_OVERRIDE=emulated`로 별도 트리에 만듭니다. rex86은 v0.0.34
  tag를 받아 옵니다. 창 제목과 보고에는 `emulated (rex86)`로 표시됩니다.

**공용 코드에 더한 것.** 플랫폼 계층의 메모리 변경 알림(보호 변경, 코드 쓰기)과 호스트 진입 상태(셀렉터, FPU,
CPUID), 실행 모델 질문 `RunsGuestOnEmulatedCpu()`, 종료 시 정지 요청 경로입니다. 실행 모델 비교용 진단
`REPIU_HLE_BOUNDARY_TRACE=<경로>`도 더했습니다(HLE에 들어간 폴트를 한 줄씩 기록). `direct`·`cache`의 동작은
바뀌지 않습니다.

### 확인한 것

| 구성 | 확인 |
|---|---|
| Win32 `direct` Debug·Release | 빌드, core probe 44/44, pumpitea(`dynamic`) 타이틀·데모 플레이 |
| Win32 `emulated` Release | GitHub의 rex86 v0.0.34로 빌드, core probe 44/44, pumpitea 타이틀·데모 플레이, 직접 플레이 |
| CI | Win32 Debug 빌드와 probe |

### 알려진 것

* `emulated`는 실시간의 약 1/8 속도라, 판정이 맞는 플레이는 아직 어렵습니다. Windows에서는 rex86의 인터프리터만
  쓰기 때문입니다(번역은 wasm용).
* Linux와 웹 빌드에서는 아직 `emulated`를 만들지 않았습니다. 다음은 브라우저 호스트와 rex86 번역 범위 확대입니다
  ([웹 이식 frontier](../analysis/web-port-frontier.md) 0절).

## rePIU v0.0.219

Changes since **v0.0.218** (issue #61). **The web (WebAssembly) port has resumed.** Its first step is a new execution
model, `emulated`, in which the game's code is run not by the PC's CPU but by the CPU emulator
[rex86](https://github.com/reexec/rex86). On Windows, pumpitea reaches its title and demo play under it. Release builds
are unchanged; `emulated` is built separately for development.

### Resolved issues

| issue | Summary | Commit |
|---|---|---|
| [#61](https://github.com/reexec/rePIU/issues/61) | Web port resumed: an emulated execution model on rex86, native first (phase 2A) | `1c9dc58` |

### Changed

**The `emulated` execution model.** rePIU's two execution models so far (`direct`, `cache`) both had the PC's x86 CPU run
the game's code itself, which is why neither can run in a browser or on an ARM device. Under `emulated`, rex86 (v0.0.34)
interprets the game's x86 instructions one by one, and the rePIU process runs none of the game's code itself.

* **The existing HLE (DOS, DPMI, Glide and the rest) is unchanged.** rex86 stops exactly where a Windows user-mode
  process faults (rex86 #69), and the instructions the HLE takes over are chosen by the same rules as the usual `dynamic`
  backend (rex86 #70).
* **Result (Windows x86 Release, pumpitea):** the title at 300 s and the demo play at 355 s, and a hands-on play
  confirmed it works. It is still slow: about 9.3 million instructions a second (about 7.4 fps), where the usual build
  shows the title at 30 s.
* **Measured:** a game frame takes about 1.25 million instructions, so real time (60 fps) is estimated to need about
  75 MIPS -- the figure that decides what must get faster for the web.
* **Building:** in its own tree with `cmake -A Win32 -DREPIU_EXECUTION_MODEL_OVERRIDE=emulated`; rex86 comes from its
  v0.0.34 tag. The window title and the reports show `emulated (rex86)`.

**Added to shared code:** the platform layer's memory change notifications (protection changes, code writes) and host
entry state (selectors, FPU, CPUID), the execution model question `RunsGuestOnEmulatedCpu()`, and a stop request on
shutdown; plus `REPIU_HLE_BOUNDARY_TRACE=<path>`, a diagnostic for comparing execution models that logs each fault the
HLE receives. `direct` and `cache` behave as before.

### Verified

Win32 `direct` Debug and Release: build, core probe 44/44, pumpitea (`dynamic`) title and demo play. Win32 `emulated`
Release: built from rex86 v0.0.34 on GitHub, core probe 44/44, pumpitea title and demo play, hands-on play. CI: the Win32
Debug build and probes.

### Known

* `emulated` runs at about an eighth of real time, so play with correct judgement is not yet possible: on Windows only
  rex86's interpreter is used (its translation targets wasm).
* `emulated` is not yet built for Linux or the web. Next are the browser host and wider rex86 translation (section 0 of
  the [web port frontier](../analysis/web-port-frontier.md)).
